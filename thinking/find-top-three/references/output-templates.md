# 输出模板

把这些模板当作可调整的结构。不要机械填满所有字段，也不要让格式压过真实对话。

## 目录

1. 开场回复
2. 模型快照
3. 多轮探索回复
4. 显式修正判断
5. 准备收敛
6. 最终三件事
7. 信息不足时的临时回答
8. 持久化讨论文件

## 1. 开场回复

上下文很少时使用：

```markdown
我先不给你拍脑袋列三个答案。现在能确认的是：这些事项里混合了___；但目前还没有足够证据判断谁应该进前三。我的暂时假设是___，它还需要验证。

最可能改变排序的是下面___个问题：

1. ___？
2. ___？
```

如果用户已经提供丰富上下文，在问题前先给出一个临时判断。

## 2. 模型快照

复杂讨论需要与用户对齐时使用：

```markdown
我目前对你的理解：

- 已确认事实：___
- 你的解释：___
- 我的当前假设：___（置信度：低/中/高）
- 可能的反证：___
- 因此当前优先级更像是：___

最值得补的不是更多背景，而是：___
```

不要暴露隐藏思维链，只展示简洁、与决策相关的证据和理由。

## 3. 多轮探索回复

每一轮只展示足以帮助用户校准模型的内容：

```markdown
这轮信息改变了我对___的判断。

- 现在更可能是：___
- 仍然不能确认：___
- 如果___，优先级会倾向A；如果___，会倾向B。

所以下一条最值得问的是：___？
```

不要为了显得有产出而在每轮重复列出三个完整候选。

## 4. 显式修正判断

```markdown
这个信息改变了我前面的判断。

- 原判断：___
- 新证据：___
- 现在的判断：___
- 对排序的影响：___
```

## 5. 准备收敛

```markdown
目前排序已经比较稳定。我最后检查了一遍，剩余未知里最可能改变结论的是___。

当前最强的替代方案是___。它暂时没有进入前三，因为已有证据显示___；如果___，它会取代___。

在最终确定前，我还需要确认：___？
```

如果确实不存在可询问的高影响未知，可以跳过这段，直接给最终结论。

## 6. 最终三件事

先给核心判断，再给三张优先级卡片：

```markdown
你当前真正要解决的，不是___，而是___。

### 第一件事：___

- 为什么是现在：___
- 它保护或解锁什么：___
- 当前阶段目标：___
- 衡量信号：___
- 下一步动作：___
- 暂时不做什么：___
- 风险或复盘边界：___
- 置信度：___

### 第二件事：___
……

### 第三件事：___
……

三者关系：___。其中___需要并行推进；___依赖___之后的结果。

暂时没进前三：___，因为___。

如果出现___，我会重新排序。
```

三件事的名称要具体到能够指导取舍，避免“提升自己”“搞好事业”这样的空泛标签。

## 7. 信息不足时的临时回答

用户要求立即回答、但证据仍然不足时使用：

```markdown
基于目前信息，我的临时前三是：

1. ___（置信度：___）
2. ___（置信度：___）
3. ___（置信度：___）

最可能推翻这个排序的信息是___。如果只能补一个问题，我会问：___？
```

## 8. 持久化讨论文件

只有用户授权后才创建文件，并优先遵守当前仓库已有的记忆和文件规则。

建议结构：

```text
三件事讨论/
├── 用户模型.md
├── 证据与时间线.md
├── 当前三件事.md
└── 决策变更记录.md
```

### 用户模型.md

只保留当前有效模型，不保存完整聊天记录：

```markdown
# 当前用户模型

## 真实目标
## 自有资产与依赖性资源
## 约束和下行风险
## 重复行为
## 已确认事实
## 用户自己的解释
## 当前模型假设
## 足以改变决策的未知信息
```

### 证据与时间线.md

只记录关键证据：

```markdown
| 日期或阶段 | 事件或证据 | 来源 | 对决策的影响 |
| --- | --- | --- | --- |
```

### 当前三件事.md

只保留最新的确定或临时优先级、三者关系、当前行动和重新排序条件。

### 决策变更记录.md

只追加重大修正：

```markdown
## 年-月-日 — 修正标题

- 原判断：
- 新证据：
- 修正后判断：
- 实际影响：
```

不要保存无必要的私密细节。把个人信息写入长期记忆前，再次获得用户确认。
