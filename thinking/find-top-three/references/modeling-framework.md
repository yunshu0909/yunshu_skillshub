# 建模框架

把这份框架当作推理辅助，不要当成必须填满的表格。删除所有不会影响当前决策的字段。

## 目录

1. 动态用户模型
2. 问题选择机制
3. 证据纪律
4. 代理目标检查
5. 归因与反事实检查
6. 候选生成与选择
7. 多轮探索与收敛检查
8. 停止与复盘
9. 安全和范围

## 1. 动态用户模型

### 目标

- 用户明说的目标
- 目标实现后的具体生活画面
- 目标承担的功能：安全、自由、身份、证明、责任、地位、乐趣、归属
- 时间范围
- 什么状态算“足够”

### 资产

- 现金流和财务续航
- 身体、注意力、时间和情绪容量
- 可迁移能力，以及能力被重复验证的证据
- 用户拥有的产品、内容、声誉、关系、渠道和知识产权
- 来自雇主、平台、伴侣、地域、市场周期或运气，但并不完全属于用户的资源

### 约束和下行风险

- 负债、固定支出、被抚养人、合同和不可逆承诺
- 工作量、健康、家庭、地域、隐私、合规和利益冲突
- 最坏的合理情景，以及用户能否承受
- 当前真实风险与历史风险记忆之间的区别

### 历史和行为

- 具体成功及其因果要素
- 具体失败及真实损失
- 用户如何从低谷恢复
- 用户在什么条件下容易启动、坚持、逃避或过度分析
- 用户如何面对评价、拒绝、模糊、社交暴露和损失

### 用户解释

- 用户的自我叙事和世界观
- 对成功和失败的归因
- 价值观和身份承诺
- 需要通过具体案例验证的抽象标签

### 模型假设

每条会影响决策的推断都记录：

- 假设内容；
- 支持观察；
- 反证或其他解释；
- 当前置信度：低、中、高；
- 能够以最低成本改变它的问题、材料或行动。

不要悄悄把模型假设升级为已确认事实。

## 2. 问题选择机制

### 最小证据门槛

宣布最终三件事前，先确认已有足够证据完成关键取舍。“跳槽、副业、结婚、买房、减肥、学人工智能”这样的稀疏清单只能证明用户认知负荷很高，不能证明哪件事应该优先。

从四个方向寻找最少的缺失证据：

- 用户希望实现的具体结果和时间范围；
- 真实期限、现实承诺、下行风险或健康约束；
- 与问题相关的财务、工作、关系和精力基本盘；
- 候选路径背后已经被验证的资产或需求。

不要逐项盘问。只问能够区分不同排序的问题。在证据充分前，输出假设和未知构成的决策地图，不输出确定结论。

### 选择下一问

用下面的定性关系比较候选问题：

    问题价值 ≈ 决策影响 × 不确定性减少程度 × 证据质量 × 可回答性 ÷ 回答负担

不要真的计算分数，只用它比较问题的相对价值。

优先询问能够：

- 改变候选优先级排序；
- 区分两个相互冲突的解释；
- 把抽象自我标签还原成可观察事件；
- 找到真实损失、恢复、付费、需求或能力重复；
- 通过现有材料得到比口述更可靠的回答。

一个问题会打开很深的分支时，只问一个。几个问题彼此独立且容易一起回答时，最多问三个。敏感信息要说明与决策的关系，允许用户提供范围或拒绝回答。

只增加人物背景、却不影响取舍的问题价值很低，直接跳过。

### 维护问题队列

每轮只维护一个短问题队列：

- 当前最脆弱的核心假设；
- 最可能改变候选排序的事实；
- 最适合通过现实行动而不是口述验证的未知。

用户回答后重新生成队列，不要沿用固定采访提纲。上一轮答案打开了新的高价值分支时，优先追问这个分支。

## 3. 证据纪律

容易混淆时，显式使用三种标签：

- **已确认事实：** 用户明确提供，或由用户材料直接支持。
- **用户自己的解释：** 用户赋予事实的意义或因果解释。
- **模型当前假设：** 模型提出、允许被推翻的解释。

材料也可能不准确或缺少上下文。把简历、财务记录、数据截图和日记当作证据，不当作绝对真相。只有来源局限会影响判断时才专门说明。

### 情景化证据

汇总数字经常掩盖真正的下行风险。存在单一客户、单一平台、杠杆、重大承诺、健康警报或时间期限时，至少检查一个关键假设失败后的结果：

- 最大收入来源消失后，现金期还剩多少；
- 剔除熟人、单一客户或一次性项目后，需求是否仍成立；
- 完成休息或离开特定环境后，状态是否改变；
- 做出不可逆承诺后，用户还保留多少选择权；
- 核心资源或关系不再存在时，方案是否仍可执行。

选择与当前决策最相关的一项即可，不要机械跑完整压力测试。只要冲击结果可能改变前三顺序或行动强度，就必须在收敛前询问或通过材料计算。

模型发生变化时，说明：

1. 原来的判断；
2. 新出现的证据；
3. 修正后的判断；
4. 对实际排序或行动的影响。

## 4. 代理目标检查

面对用户明说的目标，在内部检查：

- 它实际想购买哪种体验或自由？
- 是否有更安全、更直接的路径提供相同价值？
- 如果结果完全不公开、没有人知道，用户仍然想要吗？
- 如果指标变好了，但生活没有变化，目标算实现了吗？
- 用户是在创造价值、降低风险，还是证明自己足够好？

不要默认“想证明自己”是不合理的。判断这种需要是在服务理想生活，还是让每次行动都背负过重的身份风险。

## 5. 归因与反事实检查

避免“全是我的能力”和“全是运气”两个极端。把结果拆成：

- 准备和选择；
- 执行和交付；
- 平台、时机、关系、市场周期和随机性；
- 承担了什么风险，又限制了什么风险。

提出反事实问题：

- 如果没有有利环境，还会留下什么能力？
- 如果没有用户自己的准备，机会能够被转化吗？
- 这种能力是否在不同环境中重复出现？
- 失败来自坏结果、坏决策过程、风险暴露过大，还是三者共同作用？

用这些问题识别可迁移资产，同时避免“成功从不算数、失败永远定义自己”的不对称记账。

## 6. 候选生成与选择

问题足够复杂时，在内部生成大约五到十个候选。候选应当是持久的结果领域、能力、系统或资产。

合并因果机制相同的候选。把具体动作还原成它服务的结果。删除代理指标，除非指标本身已经构成真实约束。

### 最强替代方案审计

不要只验证当前前三是否合理，还要主动寻找什么可能比它们更合理。

对每个入选项检查：

- 它解决的真正结果是什么？
- 还有哪条不同路径可以实现同一结果？
- 什么事实会让替代路径超过当前路径？
- 当前是否已经问到能够区分两者的证据？

特别警惕把用户提出的手段直接升格为优先级。例如融资可能服务于延长现金期，辞职可能服务于获得时间控制权，涨粉可能服务于商业需求。先比较同一结果的其他实现路径，再决定手段是否值得进入前三。

在最终输出前，至少能够解释“为什么最强的落选候选没有进入前三”。解释只能基于用户事实和清楚标记的假设，不能只说当前选项更重要。

### 入选项证据卡

对每个最终候选快速检查四类证据：

| 证据 | 检查问题 |
| --- | --- |
| 时机 | 问题有多大、何时发生、正在改善还是恶化？ |
| 机制 | 真正瓶颈或原因是什么？当前是否只有表面相关性？ |
| 可执行性 | 谁来做，用户是否有能力、时间和资源？ |
| 副作用 | 这项行动会不会损害其他优先级或不可替代资产？ |

这不是新问卷。已经有证据的项直接跳过；只有缺口会改变核心行动时才继续问。若现实中暂时无法知道，把第一步写成低成本验证，不要伪装成确定方案。

再检查两类常见执行冲突：

- **同一负责人冲突：** 一个人同时负责多个优先级时，先确认其当前负荷、真实容量，以及需要停止或移交什么。口头表示“我能负责”不是容量证据。
- **同一资源冲突：** 一个机会会占用续费、健康、现金或家庭等另一优先级所需资源时，先核算投入、回报和机会成本。

存在冲突但数据不足时，把“确认容量或单位经济性”设为第一步，不直接要求全面执行。

责任边界同样属于事实。只分配用户明确确认过的职责，不因为某人具备相邻能力就扩大其责任范围；负责人未知时保留未知，并把责任澄清写成行动。

不要伪造精确分数，按下表定性比较：

| 维度 | 判断问题 |
| --- | --- |
| 目标关联 | 它能实质改善用户真正想要的生活或结果吗？ |
| 依赖位置 | 它是其他优先级成立的前提吗？ |
| 下行风险 | 忽略它会造成严重或不可逆损失吗？ |
| 复利价值 | 进展能否持续产生价值？ |
| 可控程度 | 用户能否直接影响它？ |
| 容量适配 | 它能否在真实精力和责任下持续？ |
| 证据强度 | 这个因果判断是否扎根于当前用户的现实？ |

最终选择属于模型判断，不属于加权表格。用这些维度查漏补缺、解释取舍，不要把它们变成机械算法。

三件事可能构成：

- 一条依赖链；
- 下行保护与上行机会组成的杠铃；
- 同一个系统中的三个瓶颈；
- 跨不同时间范围的组合。

从证据中选择结构，不要事先强加结构。

## 7. 多轮探索与收敛检查

多轮探索不是规定固定轮数，而是持续消除足以改变排序的不确定性。复杂个人决策通常需要多轮，但信息完整的材料型任务可能更快收敛。

每轮输出可以包含：

- 这一轮信息改变了什么；
- 当前核心假设及置信度；
- 仍在竞争的候选方向；
- 下一条最有价值的问题。

探索阶段不要输出完整的最终三件事，以免用户把临时结构当成结论，也避免模型为了维护先前答案而降低修正幅度。

准备收敛时执行反事实检查：

1. 列出最重要的剩余未知。
2. 为每个未知构造两个或多个合理答案。
3. 对关键集中风险构造一次失败情景，判断汇总数字在冲击后是否仍然成立。
4. 分别判断这些答案是否会改变前三的成员、顺序或依赖关系。
5. 检查是否会改变某个优先级的核心定义或第一步行动，而不仅是名称。
6. 用入选项证据卡检查时机、机制、可执行性和副作用，补问会改变核心行动的缺口。
7. 为每个入选项生成最强替代方案，检查是否已经有证据排除它。
8. 只要存在会改变排序、核心方向或替代方案胜负且当前可以询问的未知，就继续探索。
9. 如果信息只能通过现实行动获得，把该行动写成验证步骤，并把最终结论标为阶段性结论。

以下情况不能单独证明可以收敛：

- 用户说了很多；
- 模型已经能讲出一个完整故事；
- 三个候选听起来都合理；
- 当前三个候选都来自用户最先提出的选项；
- 模型能够给出行动建议；
- 继续追问会让回复显得不够果断。

## 8. 停止与复盘

剩余未知改变前三的概率已经很低，或者一个小行动比继续回答问题更能提供信息时，停止采访。

发生重大人生变化后，或以季度等较慢节奏复核顶层优先级；更频繁地复核具体行动。复盘时区分：

- 结果质量；
- 决策质量；
- 运气和外部环境；
- 已经展示的能力；
- 被成功限制的下行风险。

不要因为某一天的情绪或一个噪声指标调整战略优先级，除非它暴露了真实约束。

## 9. 安全和范围

只做战略优先级梳理。不诊断心理疾病，不开治疗方案，不保证投资结果，也不给确定性的法律意见。如果高风险选择实质依赖最新外部事实，从权威来源核验。决策依赖当前对话无法提供的专业能力时，建议用户寻求专业支持。
