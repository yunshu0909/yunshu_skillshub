# Logo 设计与交付

> **运行环境：必须在 Codex 中使用。** 出图、参考图编辑和品牌场景图依赖 Codex 的图像生成工具（imagegen）。在 Claude Code 等没有图像生成能力的环境里被触发时，不要用 SVG/代码拼图冒充概念稿，直接告知用户切到 Codex 执行；只做研究、讨论或诊断且不需要出图时可继续。

把用户的偏好变成稳定的图形，再把图形变成可用资产。根据当前证据进入合适阶段，不把每次调用都变成完整品牌项目。

常见路线是：定位与用途 → 审美探索 → 方向探索 → 分层收敛 → 应用验证 → 精修与组合 → 资产交付。已有方案直接从对应阶段继续；应用问题优先退回构图，方向问题才退回探索。用户主动要求讨论时先讨论，不用大量出图代替共同理解。

## 先确定现在要解决什么

读取当前对话、用户选择及已有图稿。查看实际参考图，不凭文件名判断。简短说清本轮目标及会保留什么。

| 当前请求或证据 | 本轮动作 | 完成标准 |
|---|---|---|
| 新产品，尚无方向 | 补齐关键定位，做差异明确的视觉探索 | 用户能比较并指出喜欢的方向/特征 |
| 要求研究，或多轮都不满意 | 查询一手设计案例，提出可检验的诊断 | 区分方向、造型、构图和呈现问题；给出下轮验证变量 |
| 已选某个方向或版本 | 固定基准，做受控精修 | 能看出哪个改动有效，保留原版可回退 |
| 要一套品牌效果 | 用同一母版展示组合与场景 | 风格一致，标明尚未生产化的部分 |
| 要直接使用、保存或导出 | 确立矢量/高清母版，导出并检查 | 有实际文件、用途说明和可访问路径 |

用户只要研究时不要自动生成图；已选 A 时不要重新打开所有方向；已请求导出时不要停在展示板。已知的信息不重复问。缺失信息只问会改变下一步的内容，并继续不依赖答案的工作。

用户给出的数量和范围优先于默认探索方式。“随机做一个”表示从合理的创意空间里选一个**有依据的设计命题**直接完成，不要求再做多方向；随机不是无理由拼形。“做三个不同风格”则在形式类别上拉开差异，例如字标/字母、抽象符号、角色或徽章，而不是把同一构图换三种颜色。

## 最小设计状态

短任务可保留在对话；跨轮或开始文件交付时写入该项目的设计记录。只保存必要内容：

- **产品与用途**：服务谁、核心作用；主要出现在哪个尺寸和载体。
- **想表达的性格**：少量可区分的词，以及明显不喜欢的感觉。
- **基准**：具体文件与版本标识；若来自对照板，明确是哪一格。
- **已锁定特征**：来自用户明确选择的轮廓、颜色关系、表情等。
- **分层状态**：分别记录表达方向、轮廓、内部元素、颜色关系、构图、字标为已选/暂定/待验证；一层的选择不自动批准其他层。
- **当前假设与变量**：本轮为什么改、只改变什么。
- **结果**：用户说了什么、哪些解释仍只是设计师判断、哪些版本被否定。

不要把“喜欢这张图”扩张为批准新字体、新口号、应用替换或发布。不要把模型自己推荐的版本记录成用户选择。

首次概念里由设计师补出的颜色、字体方向、标志类型和使用场景都属于**设计假设**；在用户明确选择前不要记成品牌规范。

## 定位与研究

定位用于选择表达，不要求 Logo 把功能逐项画出来。区分角色/吉祥物、品牌标志、字标组合、应用图标：可共享身份，但不必共享完整构图。

用户要求联网研究时，优先查品牌官方规范、设计公司原始案例和设计师复盘。每个案例提取：问题、做法、适用条件；随后说明对当前作品的推论。给一手链接，区分资料事实和自己的视觉判断。案例数量以能回答问题为准，不堆参考墙。

需要研究思路时按问题读取 [references/design-research.md](references/design-research.md)，将来源事实、可迁移原则、本轮验证动作分开。研究结束必须落到一个设计决定或下一轮对照；历史案例不代表当前平台规范，遇到跳转/失效不假装仍可核验。

借鉴方法与约束，不复刻辨识性轮廓或构图。不能凭“由 AI 生成”宣称原创或已排除近似商标。一般探索不扩张为法律审查；用户要求近似检索时再做并说明范围。

页面设计风格可以提供产品背景，但不能直接推导 Logo 必须是什么样。不要把某类产品默认等同于渐变、星芒、代码括号或机器人。

## 探索与反馈诊断

需求含糊、用户想讨论或难以描述审美时，先读 [references/co-design.md](references/co-design.md)。每轮给用户可判断的具体对象，围绕一个主要问题交流；不用长问卷，也不让用户独自承担“说明白审美”的工作。

首次出图或批量探索前读 [references/exploration.md](references/exploration.md)，其中包含生成前的设计状态和交付检查。

初期比较有意义的表达方向，例如字母标、抽象符号、角色型；按需求选择，避免同一图形换色冒充不同方向。轮廓、黑白关系通常先于材质与装饰；若颜色关系本身就是待验证问题，直接比较颜色关系。

生成首次概念前，先在内部或交付说明中明确三件事：

- **本轮对象**：独立符号、字标组合还是应用图标；不要用一张图同时假装三者都已解决。
- **核心视觉机制**：用一句“通过什么形状/关系，表达什么品牌属性”说明设计命题；生成结果必须仍能用这句话解释。
- **潜在误读**：检查明显且与产品有关的错误联想；没有明显问题无需硬凑。重大误读作为待验证假设，不用设计说明强行消解。

用户选中方向后保留基准，围绕少量变量比较。每版编号稳定、参照条件相同、解释它改变了什么；不必固定出六张或九张。

尽量按方向、轮廓、内部元素、颜色关系、构图逐层收敛，允许针对当前问题调整顺序。喜欢角色不等于喜欢当前配色；喜欢反色不等于批准新轮廓。小尺寸和真实载体应在候选形成后尽早参与判断，不等品牌展示全部完成。

“空”“怪”“普通”“不像 Logo”是需要解释的反馈，不是自动加元素的指令。先看它发生在哪个载体、尺寸、版本：

- 空：可能是内部重心、图形占比、外边距或前景/背景关系。
- 怪：可能是轮廓接合、五官位置、光学重心，也可能是风格不适合。
- 普通：可能缺少独特轮廓，也可能只是展示方式抹掉了已有特征。
- 不像 Logo：区分角色插画过重、识别不稳定、应用构图不足，以及纯粹不喜欢。

这些是候选解释，不是固定诊断。提出最少的可检验假设，在对照里验证。连续几轮没有改善时停止扩大变体数量，回到最近认可的基准，审查变化是否失控。

需要实际提示词和退步案例时读 [references/iteration.md](references/iteration.md)。

## 生成与精修的分工

- 栅格概念图、参考图编辑和品牌场景图，用当前环境的图像工具；可用时遵循 imagegen skill。提示词明确基准图片、保留特征、单一变化和不增加的元素。不能用代码处理绕过环境的图像编辑规则。
- 每轮检查实际输出：文字、背景、轮廓、颜色、缩略图是否匹配；展示光晕/透视等干扰比较时修正，不拿呈现技巧当设计改善。
- 概念稿交付前按 [references/exploration.md](references/exploration.md) 做轻量检查。图像工具违反关键约束时，围绕单一问题受控修正；反复仍无法消除的渐变、质感或几何漂移要明确披露，不能把高分辨率 PNG 当作接近生产完成。
- 生成图不能证明精确尺寸、像素一致性或真实小尺寸表现。不要声称生成对照板是严格控制变量的实验。
- 到可用资产阶段，优先使用已存在的可编辑源；用户授权生产资产时，可重建纯路径矢量。说明重建与原栅格并非逐像素相同，进行并排检查。不要把位图嵌入 SVG 冒充矢量。
- 一旦有母版，大小、颜色变体和生产预览由同一母版确定性导出，不再靠多次生成保持一致。

## 应用与交付

品牌展示按用户用途取舍：主标、字标组合、深浅底、单色、应用图标或实际使用场景。不要为“一套 Logo”自动添加名片、口号和整套营销物料。字标是独立设计决策，生成稿里的字体不自动成为正式字体。

判断应用图标时，看实际尺寸、前景/背景、边距和平台处理；完整角色可以与图标构图不同。图标变体应保留身份，不用嘴、胸章等细节机械填空。

交付前读 [references/delivery.md](references/delivery.md)。确保预览稿与正式资产分开，链接指向真实存在的项目文件。用户选中方向后可以继续已授权的精修与导出，但替换应用、发布和商标申请属于额外动作。
