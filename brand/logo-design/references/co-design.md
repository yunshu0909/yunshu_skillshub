# 和用户一起找到方向

在定位尚不清晰、用户要求讨论或只会说“普通/空/怪”时读取。

## 用具体对象帮助表达

先从已有材料推断产品和用途，最多聚焦当前最影响设计的一两个未知项。不要一口气问目标受众、价值观、竞品、颜色、字体、预算等完整问卷。问法应贴近使用：用户第一次看到图标时应感到可信、轻松还是兴奋；主要看在 Dock、包装还是网页标题上。

用户说不清风格时，由设计师准备少量差别清楚的参照或描述，例如“安静的工具感 / 有性格的伙伴感”。说明每项的具体视觉差异，询问更靠近哪一种、哪部分不喜欢。参考借鉴特征而非复制符号；若需要图片且用户允许出图，做小规模视觉对照。尚未允许出图时可先用简短描述讨论。

## 每轮让一个问题变清楚

用“已知偏好 → 当前不确定点 → 可判断的对照 → 用户反馈 → 更新选择”推进。只问会改变下一步的问题，使用当前环境允许的提问通道，不在每个步骤索要许可。

- 先展示，再解释；避免用长篇寓意引导用户觉得作品应该好看。
- 给出自己的建议和理由，但保留用户否定它的空间。
- “更喜欢上一版”是有效反馈：恢复具体旧文件，比较改了什么，不把用户描述成反复无常。
- 把反馈拆为已经喜欢的部分和待解决的部分。用户说“喜欢圆形但空”，先保留圆形；局部反馈不足以推翻方向。
- 模糊反馈有几个合理解释时，先表达为假设，可做对照或提一个关键问题，不宣布已找到原因。

## 分层记录

| 层 | 状态 | 证据/基准 |
|---|---|---|
| 表达方向 | 已选/暂定/待验证 | 用户原话与文件 |
| 轮廓与比例 | 已选/暂定/待验证 | 对照格编号 |
| 内部元素 | 已选/暂定/待验证 | 表情、负形等 |
| 颜色关系 | 已选/暂定/待验证 | 与轮廓独立记录 |
| 场景构图 | 已选/暂定/待验证 | 实际尺寸和载体 |
| 字标 | 已选/暂定/待验证/本轮无 | 字体方向与组合 |

不用每轮把整张表发给用户。对话里简短复述变化，跨轮文件记录保存完整证据。一个层级通过后进入已授权的下一步，不重复确认；需要用户偏好才能分支时才继续讨论。

## 研究如何改变设计

研究前写出问题，例如“角色不适合专业工具，还是完整角色放进图标的构图有问题？”查到案例后按“来源事实 → 可迁移原则 → 当前推论 → 下一步”整理。下一步必须具体，例如同一角色比较完整造型和脸部构图；不能只有“更专业、更简洁”的抽象结论。

## 避免假协作

设计师不能自己编造用户的选择，再把它当作真实批准。多 agent 模拟测试中的反馈必须标为模拟输入；不能把模拟满意度当真人审美验证。真实用户没有回应时，保留偏好未定状态，可继续不依赖它的工作。
