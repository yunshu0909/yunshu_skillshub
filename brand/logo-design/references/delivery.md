# 从概念到可用文件

用户要求保存、导出、直接使用或资产打包时读取。

## 范围与文件夹

按用户指定路径或项目约定新建独立目录，不覆盖旧版。开始前说明位置和将新增的文件。只创建实际需要的结构，例如：

```text
Brand-Logo/
  logo.svg                 可编辑主标
  logo.png                 最容易直接使用的默认文件
  png/                     所需尺寸
  platform/                按需提供 ICNS / ICO 等
  source/                  源文件或可重复导出脚本
  reference/               已选稿、展示稿
  preview.png              真实资产生成的检查图
  README.md                文件用途、来源与重建差异
```

这是资产包结构，不是 skill 包结构。不要为了填满目录生成无用文件。将项目文件保存到工作区；生成工具缓存可以作为备份，不能是唯一来源。

## 母版

- 优先已有矢量；没有时可在用户授权下重建，并明确说明。
- 所有衍生文件共享几何、颜色与眼睛/负形定义。反白、黑白版检查负形是否正确；不要把透明眼睛错填成只适用于白底的白块。
- SVG 不依赖外部图片、字体或脚本。需要字标时确认字体与用途许可；最终可转路径，保留字体信息，不虚构授权。
- 标志颜色可以从选定稿规范化为具体色值，记录该选择，不声称是精确提取；不顺带改页面 UI tokens。
- 别把“能打开的 SVG”当作“视觉上忠实”。同时查看基准与重建稿的轮廓、重心、眼距、凸起和空隙。

## 导出

根据使用场景选择格式，不机械输出全套：

- SVG：缩放、网页、设计工具。
- PNG：常见上传入口；标明尺寸、透明范围。包含蓝色底板的 Logo 可仅在圆角外透明，不能让用户误以为整个底板都透明。
- 独立符号：需要无底板角色/标志时另导出，不覆盖主标。
- ICNS：macOS 应用；ICO：Windows/favicon 按需。检查平台尺寸与安全边距；不使用 SVG 改扩展名代替。
- ZIP：打包源文件、资产和用途说明，不只打包一张展示图。

导出使用环境现有可靠工具。新写脚本要真正执行，依赖从当前环境发现，不写死另一个用户的本机路径。不要把特定品牌贝塞尔坐标做成通用 skill 的默认图形。

## 交付检查

检查有意义的结果，不为低风险导出引入庞大的测试流程：

1. 文件存在、能解码，实际尺寸/格式与名称一致。
2. SVG 是真实可编辑路径或形状；无外部依赖。
3. PNG alpha、图标圆角、独立符号负形正确，明暗背景无残留白边。
4. 用真实导出文件查看大图和目标小尺寸，关注眼睛合并、细线消失、边缘裁切。需要时从母版做有记录的小尺寸光学校正，不把各尺寸重新生成成不同标志。
5. 平台图标能由相应工具读出。若仅验证容器与尺寸，别声称已在真实 Dock 完成测试。
6. ZIP 包含正式资产；展示稿、暂定字标和最终文件区分清楚。

最后直接给一个推荐使用文件，再给源文件/整包链接。说明已验证什么，以及是否替换了应用资源；未请求应用集成时不自动修改代码或发布。
