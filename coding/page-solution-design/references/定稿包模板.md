# 定稿包模板

用户明确说「就这个」之后，一个页面的全部定稿装进一个文件夹，开发（人或 AI）只读这个文件夹。

## 目录

```
specs/<单元>/<页名>-定稿/
├── README.md                          读的顺序 + 冲突优先级
├── 前端设计定稿-<页名>.md               开发入口，自足，含可移植代码
├── NN-<页名>-高保真-全状态.html          定稿视觉件（上方交互流程 + 下方状态目录；豁免页只有目录）
├── 状态清单-<页名>.md                   编号表，PRD / 测试用例逐条对应
├── 2-design-<页名>.md                  设计过程事实源（三层结论 + 回流）
└── NN-外壳与样式包来源-<第一页>.html     第一页定稿的副本（第二页起才有）
```

- **第一页只有五件**，没有外壳来源副本；从第二页起六件。
- 序号 `NN` 沿用本单元 `_review/` 的流水号，文件搬进定稿包后**不重编号**。
- 高保真、全状态板与交互流程图**合并成一份** `NN-<页名>-高保真-全状态.html`，`NN` 取全状态板的序号。流程在上、状态目录在下，两者用同一个渲染函数（SKILL 第 5b 步）。
- 设计文档在定稿包里统一叫 `2-design-<页名>.md`，是协议位置那份的**副本**；协议位置那份是真理源，第一页在协议位置叫 `2-design.md`。

同时：过程板、作废板搬进 `specs/<单元>/_review/_作废-探索过程/`（搬进去就不用再加 `-作废` 后缀）；上层 `specs/<单元>/README.md` 登记定稿包为该页唯一入口；grep 一遍 md 里没有旧路径；定稿 HTML 里内嵌的真实数据（花费、路径、对话正文）按 SKILL 第 4 步脱敏，或抽成同目录 json 并在 §11.1 标注，不把本机私有内容随包留存。

## README.md

```
# <页名> · 定稿文件夹

| 文件 | 读的顺序 | 作用 |
|---|---|---|
| 前端设计定稿-<页名>.md | 1 | 开发入口 |
| NN-<页名>-高保真-全状态.html | 2 | 定稿视觉件：上方交互流程（点缩略图看原尺寸），下方状态目录；本目录起 python3 -m http.server <固定端口> 预览 |
| 状态清单-<页名>.md | 3 | 编号表（六类 N 条） |
| 2-design-<页名>.md | 需要时 | 设计过程事实源 |
| NN-外壳与样式包来源-*.html | 需要时 | 外壳与样式包来源（第二页起才有） |

冲突优先级：前端设计定稿 > 状态清单 > 定稿 HTML > 2-design。
同一文件内 §3 文字规格与 §11 代码冲突时，以 §11 为准（代码从定稿 HTML 原样抽出，文字是转述），发现即改文字。
与项目现行规范的冲突逐条抄在这里，不指向包外文件。
```

条数、端口这类数字写进去之前先数一遍，别凭印象写。

## 前端设计定稿-<页名>.md

### 头部必写四行

十一节之前先写：状态与日期、「本文自足」声明、与同包其他文件的冲突优先级、**页面外的连带改动**（侧栏条目改名、路由、菜单项——十一节收不住它们）。

### 十一节

| 节 | 写什么 | 来自 |
|---|---|---|
| 1 这页干什么 | 一句话任务、范围、不含 | 第 1 步 |
| 2 页面结构 | 区域树、排列规则、窗口尺寸口径、**外壳规格内联**（不指向第一页文档） | 第 2 步 |
| 3 主组件规格 | 每个区域每个元素的尺寸 / 字号 / 颜色 / 间距 / 对齐，表格 | 定稿 HTML 的 CSS |
| 4 弹层 / 控件规格 | 每行控件、保存与非法输入规则、**每个动作的 Toast 文案** | 定稿 HTML |
| 5 状态总表 | 状态 × 区域一张表，**首列写状态清单编号**（A1/C7，可多个），每格写显示什么，**末列写状态目录的窗口号**；表前一句指向定稿 HTML 的交互流程（状态之间怎么走） | 状态清单 |
| 6 数字与文案规则 | 单位、小数、零值、日期、按钮文案、数字方向 | 第 6 步 |
| 7 数据与存储逻辑 | 存储结构、计算公式与**区间闭开 / 日界**、来源表（只读字段名）、**新增 IPC 的 channel 名 + 入参 + 返回 + 失败形状**、引用的现有服务给**签名和字段名**、算钱的给**单价表路径** | 第 1 步来源表 + 第 2a 步 |
| 8 组件与实现契约 | 新增 / 复用 / 退役 / 新增 token 落点；新增组件给出规格，不写「与某页一致」 | 2-design §4 |
| 9 交互清单 | 点什么发生什么，明确「无」的项 | 状态清单 E 类 |
| 10 交付自查 | 可勾选项；**定稿时逐条勾完，留空框视为未定稿** | skill 自查表里可验证的那部分 |
| 11 定稿 HTML 与可移植代码 | 见下 | 定稿 HTML |

总表行数少于状态清单条数是正常的，但**每条清单编号必须能在总表里找到归宿**，找不到的要么补进总表，要么在清单里标「不影响布局，仅文案」。

### 第 11 节怎么抽

抽之前先在定稿 HTML 里写导出锚点（第 4 步就该埋）：

```
/* @export:card 卡片与弹层 */ … /* @end */
// @export:render 渲染逻辑        … // @end
```

按锚点切片，**不手抄**。切完做三件事：

1. **补基础前提。** `box-sizing`、正文字体栈（含中文字体）、基础字号行高、`font-variant-numeric` 这类写在 `<style>` 顶部的规则，虽然长在演示壳区域里，**凡组件样式依赖的都要单列一个「基础前提」代码块**。整段当演示壳跳过，抄过去的卡片就长不成稿子的样子。更稳的做法是把这些属性直接写到组件规则上，不靠继承。
2. **剔死代码。** 用 `grep -c` 核一遍：每个抽出来的函数被调用过、每个 class 在标记里出现过。上一页遗留的未调用函数、未使用 class 要么删，要么在代码块上方标「遗留，不移植」。
3. **grep 转义残留**：`\$`、`{{`、`&lt;` / `&gt;` / `&amp;`。

演示取数（内嵌的真实数据常量、演示用的 cost 函数）单独说明「实现时换成服务层」，不要让下游以为是业务逻辑。

交互流程图（流程数据、渲染、放大查看）和现有组件的示意（Toast、确认弹窗）列进 §11 末尾的「演示层（不移植）」，逐个写明实现用哪个组件：组件名 + 路径 + 用到的参数（如 `Toast` 的 `type="error"`）。

## 定稿的标志

- 文件夹件齐（第一页五件，第二页起六件）。
- 定稿 HTML 上方有交互流程（按 SKILL 第 5b 步豁免的纯展示页除外，2-design 写明理由）：会写入或可能失败的动作走到成功与失败，有确认的加取消。
- **自足可验**：全文 grep「见 / 沿用 / 与…一致 / 现有」，每一处要么指向本包内文件，要么后面跟着够用的规格值；实现路径上指向包外的一处都不能留（过程件那种明确标注「实现不需要」的除外）。
- §3 文字与 §11 代码无冲突（字号、阴影层数、颜色这类最容易两说）。
- §10 自查表逐条勾完，含 `scripts/check-layout.js` 跑绿、playwright 各窗口截图看过。
- 上层 README 指向它，旧路径为零。
