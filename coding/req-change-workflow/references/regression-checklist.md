# 需求变更回归清单

按本次变更的范围选择检查，并记录真实命令与结果。只写用例或列出命令不代表执行通过。

## 1. 基线与目标行为

- 从代码确认当前入口、数据流和已有测试。
- 逐条验证本次验收标准的正常路径、失败路径与边界。
- 验证要求保持不变的相邻功能。

## 2. 自动化与人工检查

- 运行项目已有的相关单元、集成、端到端或冒烟测试；增量用例复用原回归基线。
- 涉及界面时运行真实页面，核对关键状态、交互与布局。
- 自动化无法证明的部分记录人工检查方法和观察结果。

## 3. 按变更选择专项验证

- 数据写入：失败恢复、重复触发、并发、原子性与幂等。
- 权限或鉴权：首次使用、授权失效、拒绝和续期。
- 迁移或兼容：旧数据读取、升级中断、回滚路径。
- 网络与异步任务：超时、取消、失败提示和重试。
- 配置或默认值：未设置、已自定义、恢复默认与升级。

## 4. 验证记录

记录变更点、执行命令、通过与失败项、人工补测、未验证原因及回滚方法。未执行、被阻塞、跳过的检查分别写清楚。

Chrome 扩展项目可参考 [扩展示例](chrome-extension-regression-example.md)，检查实际存在的入口；改动 manifest 或 service worker 后先重载扩展。
