# 边界清单

第 4 步发给审核者，也给自己在第 1 步先过一遍。每一类记录三样之一：**已覆盖的规则编号** / **不适用的理由** / **待定的问题**。不靠「想过一遍」。

| 类 | 要想的情况 |
|---|---|
| 半途变更 | 执行中世界的状态变了：用户改了设置 / 关了某项 / 改小了数量；**别人先合了主线**；依赖或工具升级了；环境变了——立刻生效、下一次生效，还是这一轮先走完；已经通过的结果（签收、审核、证明）会不会因此作废 |
| 替换与继承 | 执行者换了（关掉、挂了、超时）：替补接过什么（意见、计数、状态）；会不会和正在进行的撞车 |
| 计数与额度 | 按什么单位算（每个执行者 / 每个环节 / 整个任务）；换人、升级、改规则会不会清零；自动追加会不会无限循环；页面显示的额度和后台记的是不是同一个 |
| 重复与重试 | 重复点击、消息重投、恢复执行会不会重复写入或重复扣费；成功了但响应丢了怎么办 |
| 取消、退出与恢复 | 用户取消、应用关闭、崩溃后重开：哪些结果算数；「接着做」的范围有没有和第一次一样 |
| 超时与进程 | 超时后真的停了没有（连子进程）；迟到的结果算不算；会不会锁死或重复执行 |
| 多步写操作 | 每一步断在中间怎么认出来、怎么倒回去（要有步骤表，正向反向都要）；一步进行中原件被外部改了；备份 / 暂存写完有没有立刻验；**恢复路径 × 每一条例外**交叉过一遍（恢复时有没有继承第一次的例外范围） |
| 两份数据不同步 | 分两步写时中间断电；源数据变了导出没更新（测试失败、下架、改名、删除）；谁是唯一写方 |
| 并发与隔离 | 多窗口、多进程、两端版本不同；不同项目 / 账号 / 配置目录会不会串数据；共用的记录（如不同名字共用的忽略记录）被两边同时改 |
| 权限与授权 | 谁有权读写；没权限时用户看到什么；授权被撤销、Key 过期、登录失效后，进行中的和以后的怎么办 |
| 同一逻辑多入口 | 同一条判断被几个入口共用（后台静默 / 用户点击、页面 / 命令行）：各入口的结果、提示、副作用是否一致 |
| 内部结构 | 对象内部还有结构时（子文件、内部链接、嵌套目录）：复制、比对、摘要是否一致，内部链接和外部链接分开处理 |
| 接口契约 | 两端共用的枚举、字段、状态值是否一致（前端认的状态值和后端返回的是不是同一套） |
| 文件损坏、手改与拖垮 | 读不出、格式不认识、字段缺失、超范围；手改能不能用；**一个坏文件或一次慢查询会不会拖垮整个页面或整批任务** |
| 默认值与升级 | 默认值是不是一份正本；改过的、碰巧等于新默认值的怎么算；新旧版本混跑——旧的东西遇到新执行器、**新的东西遇到旧执行器**（要明确拒绝，不能静默降级） |
| 身份与改名 | 改名、删除后同名重加、临时消失又回来：算同一个还是新的；原来的位置 / 设置保不保留；被忽略 / 关掉的东西后来消失或断链，相关提示和记录怎么办 |
| 能力不匹配 | 某个设置值对某个对象不再支持；对象没有这个能力时传什么 |
| 时间与数值 | 时区、日界、夏令时、时钟被改；零、负数、精度、取整、上下限 |
| 缓存与同步 | 过期数据、离线、乱序返回、冲突合并、全量与增量、删除标记 |
| 容量与外部副作用 | 磁盘满、队列满、限流、长任务；部分成功怎么补偿；会不会多花钱 |
| 迁移与回退 | 中断后重跑、备份恢复、降级、新旧共存；什么时候才能删旧数据；正在跑的旧任务怎么办 |
| 交付之后 | 交付后清理、升级工具或插件，会不会让「已交付」的检查失效 |
| 怎么证明改对了 | 每条关键规则用什么证据证明；**什么才算真的跑了**（全部跳过、零条、预期失败不算通过）；记录里写的命令 / 范围是否等于实际执行的；原来就失败的旧测试怎么区分；「真实」验证里有没有用假的替身（有就要让用户知道） |
| 回放与审计 | 事后能不能知道当时用的是哪一版规则；只记指纹够不够，要不要存完整快照 |
| 隐私 | 导出、送审、日志里会不会带出凭证、用户名、本机路径 |
| 用户决定之间 | 用户定的几条放在一起会不会互相打架 |
| 两处写法不一致 | 同一件事在计划、方案页、代码、文档、验收页里写法不一样（例如一处说是「测量目标」、另一处说是「硬门禁」）——要摆出来说「材料自己打架了」，不是当成新选择题 |

## 给审核者的提示词要点

1. 先列「用户已拍板的决定」，写明不许推翻、只指出冲突。
2. 给材料路径：规则 JSON、前端状态清单（或触点表）、交互流程数据、现有代码目录。
3. 要求按上表逐类给出「已覆盖 / 不适用 / 问题」，问题分 P0 / P1 / P2，每条「涉及编号 + 具体场景 + 建议规则 + 案例」，最后列「要用户拍板的业务题」（带推荐和理由）。
4. 只读，不改文件。
