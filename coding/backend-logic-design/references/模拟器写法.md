# 模拟器写法

什么时候做：规则是「几个条件 → 一个结果」，条件之间有先后或互相影响（挑选、分配、排序、计数、上限、跳过），或者是时间类规则（什么时候刷新、什么时候过期）。只有一两个条件的，卡片里的小例子就够。一页可以有多个模拟器，每组卡片一个（`cards.json` 里该组写 `"sim": "sim-<名>.html"`）。

## 两种常见样子

**挑选型**（样板：`examples/审核配置/sim-挑模型.html`）

1. 上面一行是条件：下拉框、勾选框，用用户的说法命名。
2. 中间是对象列表：真实名字；能调顺序（↑ ↓）、能开关（点名字）。
3. 每一行右边写结论和原因：「派第 1 个」「跳过：写代码的那家」「没打开」「已经够数」——原因是最有用的部分。
4. 底部一句总结论：完全满足绿色，打了折扣（比如不够数）橙色，停下红色并写原因。

**时间轴型**

1. 上面是条件：比如「窗口在前台 / 后台」「文件是在第几秒新建的」。
2. 中间是一条时间轴：0 秒、10 秒、30 秒……每个刻度写发生什么（扫描、发现、显示、过期）。
3. 可以拖一个「现在」指针，或点「快进 10 秒」，看页面此刻显示什么。
4. 底部一句：「第 N 秒你会在页面上看到它」或「它要等你切回窗口才出现」。

## 必须做到

- 注释写它覆盖的规则编号；卡片标题下也写。**写明它没覆盖的条件**（比如「健康检查失败没有模拟」），不让用户以为全覆盖了。
- 交付前列 5–10 组「输入 → 预期」并逐组跑过，记在第 4 步的审核材料里；规则改了，模拟器同一次改，重跑这几组。
- 样式用模板里的 `.sim / .ctl / .ml / .mr / .out`；手机宽度下每行结论换到下一行，不挤成一字一行（模板已处理）。
- 片段里的脚本包在 `(() => { … })()` 里，元素 id 统一加自己的前缀（如 `sp-`），只操作自己的元素；`build.py` 会拒绝两个模拟器用同一个 id。
- 浏览器截图做不了时（沙箱、无界面环境），在报告里写「未截图核验」和原因，不能把脚本里的逻辑演练当成页面核验。
