# 教学法操作手册

SKILL.md 是纲，这里是每一步的具体打法。开工前整篇读一遍。

---

## ① 抽干货

> 本手册里的 `templates/`、`references/` 均相对于当前 `article-study` skill 目录。先定位该目录，不要假定它安装在某个 Agent 的固定路径。

### step 0 · 先粗判类型

**确认/创建学习目录**（`mkdir -p`，全程用绝对路径）。然后按**材料形态**选打法：

| 材料形态 | 打法 |
|---|---|
| 单个网页 / 单篇文档（多数情况） | 整篇抽干货，一份 `资料-<主题>.md` 到底 |
| 已知的多篇 / 长文 / 2-10 万字 | 先出目录地图 `资料-<主题>-地图.md`（每章一句话 + 值不值得学），**学到哪一讲抽哪一章**；"不再回原文"降级为"不再回已抽过的部分" |
| 整本书 / 几百页 PDF | **禁止不问就整本切讲次**。先列目录问用户："你想解决什么问题？这次只学哪几章？" 砍到 5-8 讲的量再开工，其余记进学习计划的「以后再说」区 |

> **URL 类材料不抓下来是不知道字数的**：先走 step 1 取材，拿到正文后回来对表（多数网页文章直接走第一行）。PDF / 本地文件可以直接分级。

PDF 用当前环境可用的 PDF 读取能力按页码分段读，每段控制在可完整核对的范围，并在目录地图里记录已覆盖页码。**读多少写多少**——读了前 30 页就当整本抽完了，后面"不再回原文"会把这个残缺锁死成事实源。

**500 页切成 30 讲不是勤奋，是没做取舍**——用户会在第 4 讲跑掉。学习计划要能在两周内跑完，超了就砍范围，不是加讲次。

### step 1 · 取材

**优先用当前环境可用的专用取材能力**（如已安装的 `agent-reach`）——拿到正文后回到本流程。没有专用能力或抓取失败时，再用浏览器或网页读取工具。遇到登录、验证码或反爬时不要伪造正文，请用户提供可读版本或文件。

> 边界：调用其他工具取材 ≠ 转交主流程。反过来，用户要的只是"调研 X 上大家怎么说"（没有"学"的意图），整件事归调研/取材工具，本 skill 不介入。

### step 2 · 整理成结构化笔记

用 `templates/资料模板.md`，产出 `资料-<主题>.md`：

- 图片里的信息翻成文字（截图信息不整理，后面就丢了）
- 绕的表述翻成人话；原文金句单独摘出（课件要引用）
- 头部标注：来源、作者、日期、原文链接、整理日期
- **推论要标记**：整理时冒出的"原文没直说但成立"的推断，单独标出来（红线 5）

之后全程用这份笔记取材，**不再回原文**（长材料按 step 0 的降级版执行）。

**为什么不能省**：原文是给同行看的，笔记是给学习者用的——顺手就把"翻译"做完了。

### 没有材料时（"带我学 X"、"我想学会 Y"，但没给链接）

**不许凭记忆开讲。**一旦编出一份没有出处的资料，"不再回原文"会把编造锁死成唯一事实源。按顺序走：

1. **先在用户身边找**：他自己的 skill / 文档 / 代码 / 过往项目产物往往就是最好的教材，而且天然满足第④步。
   例："我想学会写 PRD" → 你本地就有 `prd-test-writer`，拿它当教材，边学边挑它的毛病。
2. **再去外面找**：用可用的取材或网页搜索工具找 1-3 篇候选，**列出来让用户挑**，不要替他定。
3. **用户就是要你直接讲**：可以，但降级说清楚——资料头部写「来源：AI 自述，无原文出处」，讲次表标「未经原文校验」，并且**免掉"不再回原文"**（随时可补材料回来重切）。

## ② 切讲次

- 按文章**自带骨架**切最省力（有五个关口就切六讲：背景 1 讲 + 每关 1 讲）。
- 一讲一个主题，控制在一次能消化完。

### 切多少讲：先量素材

| 正文字数 | 切法 |
|---|---|
| < 1500 字 | 按骨架 1:1 切，**不再细拆，且允许合并**（合并理由写进学习计划的「为什么这么切」） |
| 1500~6000 字 | 按骨架切 |
| > 6000 字 | 按骨架切完再看有没有哪讲塞了两个主题，有就拆。**任何情况下不超过 8 讲**——超了砍范围，不加讲次 |

- **一讲的下界**：原文素材撑不起「一个能出考题的完整主张」，就并进相邻讲。
- **短文章（<1500 字）减配**：只出【基础卷】、不做全景图、实操并进最后一讲。给一篇 600 字的文章配三套卷和一张全景海报是荒谬的。
- **短文章的分量从哪来**：不是注水，是「原文没说但成立的推论」+ 用户场景推演——但必须遵守红线 5，和原文观点视觉可分。

### 产出与落盘

1. 用 `templates/学习计划.md` 写 `学习计划.md`，**必填学习目录绝对路径 + 下一步**。
2. **记录跨会话入口**：如当前 Agent 已有项目级持久记忆文件，且用户的记忆策略允许，追加 `- [<主题> 学习进度](<绝对路径>/学习计划.md)`。
   - 只更新**当前会话所属项目**已存在的记忆文件；不要为这次学习擅自开启新的记忆系统。
   - 没有持久记忆能力时，说清「新会话时需要重新提供学习目录」，让用户保留路径。
3. 讲次表**贴出来给用户过一眼即可，不阻塞**（不是硬闸门）；用户没意见就直接开第 1 讲。

### 轻量档（用户选了"20 分钟讲一遍"）怎么跑

不是"什么都不做"，是**缩规模但不破结构**：

- **仍要出** `资料-<主题>.md`（否则没有素材源）
- **仍要出极简版 `学习计划.md`**：只填学习目录绝对路径 + 讲次表 + 标注「轻量档，未考核」——否则新会话的恢复协议失效、也没法接"讲完再问要不要转完整流程"
- **仍要考**：每讲末一道判断题或二选一（复用下面「用户拒绝考核」的降级档），讲次状态一律标 ⚠️
- 转完整流程时，**⚠️ 的讲次在测验卷里必须补题**

红线 2 要的是"用户产生过输出"——轻量档降的是成本，不是取消验证。

## ③ 学-考-讲循环（核心引擎）

每一讲都跑完整三步，不许跳。

### 学

- 用 `templates/课件模板.html` **整体复制起手**（复制到学习目录再编辑），写这一讲的内容。
- **课件质量下限**（缺任一即返工）：≥3 节；每节正文你自己讲透，**禁止出现"详见原文第 X 章"**（红线 1）；至少 1 个 `.analogy` + **2 个 `.yours`** + 底部 `.homework`。
- **比方要跨到用户业务之外的领域**（做菜、装修验收、开店、考驾照）——用用户自己的业务打比方，会和第④步的对号入座混成一团，比方就塌了。
- **交付动作（按顺序，别跳）**：
  1. 用当前环境的文件编辑能力落盘到学习目录 → `课件-第N讲-<主题>.html`
  2. 用环境支持的文件交付/预览方式发给用户；支持可点击本地文件链接时优先给绝对路径链接，否则用浏览器打开，最后才退而给出绝对路径
  3. **绝不把 HTML 正文贴进对话**（几百行会冲掉上下文，也没法渲染）
- 发完在对话里给**导读**：这一讲抓哪几个点、哪一节是重头戏、哪里可能卡住。**不要把课件内容在对话里重讲一遍。**

### 考

每讲末必须让用户输出，三选一（按内容性质选）：

| 考法 | 适用 | 例子 |
|---|---|---|
| 复述题 | 概念型内容 | "用自己的话讲一遍：为什么必须先看到测试失败？" |
| 动手题 | 有格式/套路的内容 | "从你项目里挑个出过 bug 的需求，写 2 条 Gherkin 发我" |
| 对号入座题 | 方法论型内容 | "你现在的流程里，这三个角色的活分别谁在干？（没人干也是答案）" |

考题写进课件底部「课堂作业」区，同时在对话里点名。

> **硬停**：课件发出 + 点名作业之后，**这一轮到此为止**——不许在同一条回复里继续讲下一讲，不许自己替用户答题。用户没回答就等着；用户说"跳过"才往下走（记进挂账）。
> 这是整个流程最容易塌的地方：一口气发三讲课件 = 「学-考-讲」退化成发讲义，红线 2、3 同时作废。

**用户拒绝考核时（"别考我了，直接往下讲"）**——不许硬顶也不许闷声放弃：

1. **降轻量档**：换成 10 秒能答的——判断题（"这句话对不对：X"）或二选一（"A 和 B，这一讲主张哪个？"）。红线 2 要的是"用户产生过输出"，不是"写满 200 字"。
2. **仍拒绝 → 说一句代价，立刻往下走**（不劝第二遍）："行，这讲不考了。提醒一下：不考就只能靠'听着懂'判断，学完的卷子我会把这几讲加重。" 笔记挂账标"第 N 讲未考核"，学习计划状态标 ⚠️。
3. **连续 3 讲未考核提醒一次**："我们三讲没验证过了，出个 5 题小卷，3 分钟。" 提醒一次即可，再拒就全留给最终测验卷回收——⚠️ 的讲次在基础卷里**必须有题**。
4. **用户连续两讲不交作业**（不是拒绝，是不回）：主动降成本——"要不要改成我出选择题，你只回 A/B？"，不要继续往下发课件。

### 讲（拧紧——最长本事的一步）

用户答完，按这个顺序回：

1. **先肯定答对的部分**，具体说对在哪（不要泛泛说"很好"）
2. **挑一到两处拧紧**——硬要求，听着对也要找出最不精确的一处
3. 用户答案里有**错误示范**时，当场放大它的价值（"你刚才亲手扮演了那个写错版的 AI"）
4. 收尾：落盘 `笔记-第N讲-<主题>.md`（用 `templates/笔记模板.md`），更新学习计划状态和「下一步」

**拧紧的形态检查（红线 3）**：拧紧那句必须是**否定/收窄结构**。写成"补充一点…"就不是拧紧，重写。

**拧紧话术库**（真实案例，照这个感觉找）：

| 用户的说法 | 拧紧成 |
|---|---|
| "多轮校核降低 bug" | 关键不在"多轮"在"性质"：**少而硬的校核 > 多而软的校核** |
| "所有逻辑都要人来校核" | **人管「要不要」，机器管「有没有照做」**——全靠人校核就撞上人力瓶颈了 |
| "开发前所有规则都要想清楚" | 不追求想全，追求**没想到的会被逼着暴露** |
| "AI 写代码越来越依赖了" | 该焦虑的不是依赖变量，而是**没有常数**（流程） |

**三个抓手**：① 把模糊词换成可判定的表述 ② 指出它撞上了前面讲过的哪个坑 ③ 补上它漏掉的第三条腿。

### 抽象概念专项：上交互演示

文字讲两轮还不通，立刻停止解释，改做**可交互 HTML**（先读 `references/README.md` 的 6 条工艺，再看物证）：

- 页面里嵌一个真能跑的最小系统（JS 模拟即可）
- 2-3 个状态切换（空壳版 / 写错版 / 正确版）+ 一个「▶ 运行」按钮
- **故意演示失败**：让用户亲眼看防线抓住错误
- 顶部写 4 步操作指引

命名：页面 `交互演示-<概念>.html`；配套能真跑的代码放同名目录 `交互演示-<概念>/`（附 README 教用户自己重跑）。

## ④ 对号入座（贯穿③，不是独立一步）

### 先锁定"具体对象"，再逐讲落点

开工时先写出一句话：**这篇文章在用户场景里的具体对象是什么**——哪一份文档 / 哪一个流程 / 哪一段代码 / 哪个 skill。

- 一句话写不出来 → **先跟用户确认，不许硬接**（红线 4）。硬接的结果是每节末尾塞一句"这跟你们系统一样要 XX"，听起来完成了对号入座，实际是废话。
- 锁定后写进 `学习计划.md` 头部，全程只用这一个对象。

### 每一讲问三个问题里的至少一个

1. **这套东西对上我自己的什么？**（现有工具、skill、流程）
2. **我的痛点在这套体系里属于哪一环？**（用户说过的每个"感觉不对劲"都要接住）
3. **拿我的真实场景走一遍是什么样？**

用 `.yours`（📌 对号入座）色块承载，**每讲至少 2 处**，且必须引用用户前面讲过的原话/工具名——不能是泛泛的"你可以把这个用在工作里"。

### 用户答不出业务场景时的降级阶梯

"没有特别的场景"通常不是真没有，是问法太抽象。

1. **换问法**："你最近一次因为这事吃过亏是什么时候？" / "你手上哪个工具、哪个流程和这篇沾边？" / "你平时最烦哪一步？"
2. **从环境里捞**：用户的 skill 目录、最近的项目、项目指令或记忆文件（如 `AGENTS.md`、`CLAUDE.md`、`MEMORY.md`），直接提名字问"是不是拿 X 当案例"。
3. **共用案例模式**：由你选定**一个**贴近用户身份的具体案例，全程只用这一个（**不许每讲换**），在学习计划里注明「场景：<案例>（用户未提供，随时可替换）」，每 2-3 讲问一次"这个案例还贴你的实际吗"。

**落点顺位**：真实业务场景 > 现有工具/skill > 用户说过的痛点 > 共用虚构案例。
红线 4 禁止的是**没有落点**，不是没有真实场景——④永远能跑，只是成色不同。

### 对比用户自有工具时

逐维度列表格，明确说出"哪块用户更强、哪块是缺口"——不要一边倒地夸文章。

## ⑤ 收官：实操 → 测验 → 讲错题 → 蒸馏 → 全景图

### 实操

- 挑一个**小案例**，把全流程真跑一遍（**要能运行**，不要纸上谈兵）。
- 角色互换：**用户当拍板人/需求方，你当执行者**——让用户体验被追问的感觉。
- 真实场景会自己长出错误，**遇到就地放大成教学点**。
- 每站产出落盘；复盘站用学到的指标**量这次实操本身**（元级应用，印象最深）。

### 测验卷

用 `templates/测验模板.html`，按它头部注释改 4 处（title / 页头三行 / case 块 / QS 数组），**逻辑一行别动**。

| 卷型 | 题量 | 设计要点 |
|---|---|---|
| 基础卷（必出） | 每讲 1-2 题 | 单选，逐讲覆盖，**换新场景考迁移** |
| 进阶卷（>6000 字才出） | 6-8 题 | 多题型（找茬多选/排序/判官/陷阱/诊断/动手写），每题埋一个诱人的错误项 |
| 综合实战卷（>6000 字才出） | 10-12 题 | **全部围绕同一个新案例**，按流程顺序推进，前面的题在后面回响；最后一题设计成"每环都做了却仍出事"的根因题 |

出卷铁律：① 全部新场景（不用课件原题）② 每题配即时解析，**解析要点破陷阱在哪** ③ ⚠️ 未考核的讲次必须有题 ④ 短材料只出基础卷、题量按体量缩放 ⑤ **每题 `tag` 必须写清来源讲次**（`第 N 讲 · <题型或主题>`，跨讲综合题写 `第 N-M 讲`）——错题回退全靠这个字段，漏写等于把回退链掐断。

### 讲错题（错题回退——兑现"可验证"的承诺）

用户报分数和错题号后：

1. 错题号 → 打开该卷 HTML，读对应题 `QS[i].tag` 里的讲次（出卷铁律⑤保证它写着）
2. 打开该讲笔记，看当时**拧紧过哪一点**
3. **只重讲那一点**（不要把整讲重放一遍）
4. **当场换新场景再出 1 题**验证——绿了才算这条补上

### 蒸馏

- **全程边学边攒** `蒸馏素材清单.md`（用 `templates/蒸馏素材清单.md`）：用户自己冒出来的想法标 ⭐、可直接抄的招、真实踩坑的教训。**不要等最后回忆**。
- 每条记：来源讲次、对标原文的什么机制、落到用户哪个工具、处置结论（改文档/加脚本/先试点/不采纳）。

### 全景图

产出 `全景图-<主题>.html`：一页总览（总纲主线 → 各站详解三栏「人干什么/机器干什么/实际拦住了什么」→ 暗线 → 对号入座的蒸馏地图），可当海报长期查阅。**短材料（<1500 字）默认不做，用户点名要才做。**

## 贯穿机制与节奏

- **挂账不阻塞**：用户**回了但答不完整、或明确说"跳过"**时 → 记进笔记「挂账」继续走，学完统一回收。
  **⚠️ 用户完全没回复不算挂账条件**——那走 ③ 的硬停（等着）。挂账治的是"答了一半"，不是"还没答"。
- **恢复协议（新会话说"继续学习"）**：
  1. **先定位再开口**：按顺序找 `学习计划.md` —— ①当前目录及子目录 ②用户 MEMORY.md 里记的学习目录 ③都没有就问一句"哪个学习目录"。**这一次确认是必要的，不受下面"不要反复确认"的约束**。
